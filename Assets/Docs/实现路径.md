## 阶段 A · 单机跑通（Day 1-6）

**目标**：主机端跑通全流程，验证玩法。所有脚本先普通 MonoBehaviour，NetworkBehaviour 化留到阶段 C。

### A1. 场景与相机（1 天）
- **文件**：`GameScene_PartyFishing.unity`
- 海面：Plane + `mat_ocean.mat`
- 4 座岛：Cylinder（沙滩）+ Cube（放鱼平台，加 Tag `FishPlatform`）+ Collider Trigger
- 相机：调整为俯视角（复用 Cinemachine，Follow=null，Position=中央上方）
- 边界：4 个不可见 BoxCollider 围地图

### A2. 玩家 & 木筏控制（1 天）
- **新脚本**：`Assets/Scripts/PartyGame/PartyPlayer.cs`
  - 裁剪自 `Scripts/Player/Player.cs`，删除 KitchenObject / cutting / interact-with-counter 相关逻辑
  - 保留：移动、朝向、Interact 事件（用现有 `GameInput`）
- **输入扩展**：`playerInputActions.inputactions` 新增 Action：`UseItem1`、`UseItem2`、`Drop`
- **临时视觉**：Cube + 桅杆 Cube，暂不接美术

### A3. 局内主控 & 波次系统（1-2 天）
- **新脚本**：
  - `PartyGameManager.cs`（裁剪 `GameManager.cs`）：
    - 状态机 `WaitingToStart / CountdownToStart / GamePlaying / GameOver`
    - 主计时 180s
    - 进入狂暴阶段（150s 触发 x2 广播事件）
  - `FishingSpotSpawner.cs`：
    - 每 30s 刷新一波
    - 1-5 波各随机生成 3 个普通点
    - 第 6 波在地图中央生成 1 个金色点
- **数值**：`ScriptableObject` `PartyGameConfig.asset`，把设计文档 §7 表格里的所有参数塞进来（后续调平衡不用改代码）

### A4. 捕鱼点 & 鱼（2 天）
- **新脚本**：
  - `FishingSpot.cs`：SphereCollider Trigger；持有 `remainFish: int`、`type: Common/Golden`、`lifetime`
  - `Fish.cs`：SO 数据（type、score、prefab 引用），只是数据不是场景对象
- **交互流程**：Player 进入 Trigger → 按 Interact 触发 `FishingAction` 协程
  - **复用 `IHasProgress`**：`FishingAction` 实现该接口，直接对接现有 ProgressBarUI Prefab
  - 读秒过程中移动即打断（监听 `GameInput.OnMove`）
  - 读秒完成：`remainFish--`；玩家木筏鱼数 +1（受载鱼上限 2 约束）
- **临时视觉**：捕鱼点用蓝色 Cube + Point Light 冒充，无粒子

### A5. 岛屿存放 & 结算（1 天）
- **新脚本**：`Island.cs`
  - `ownerPlayerIndex: int`（0/1/2/3）
  - `commonFishCount / goldenFishCount`
  - Trigger 进入 + Interact 按键：
    - 是自家 → 卸下所有木筏鱼（+对应类型计数）
    - 是他人 → 偷 1 条到木筏（受载鱼上限约束）
- **结算**：`PartyGameManager.OnStateChanged(GameOver)` → 汇总 4 岛数据 → 触发结算 UI

### A6. HUD（1 天）
- **新 Prefab**：`Assets/Prefabs/PartyGame/PartyHUD.prefab`
- 组件全用 TMP 文字 + `ButtonBackground.png` 底图：
  - 主时钟（左上）
  - 波次条（顶部，Slider）
  - 道具格 x2（左下）
  - 木筏鱼数 "0/2"（左下）
  - 排行榜（右下 4 行文本）
- **结算 UI**：单独 Panel，`SetActive` 切换

**阶段 A 里程碑**：单机可以完整跑一局 180s，看到捕鱼、放鱼、偷鱼、结算的完整循环。

## 阶段 B · 道具系统（Day 7-9）

### B1. 道具数据框架（0.5 天）
- **抽象**：`ItemDataSO`（`itemId`、`iconSprite`、`durability`）
- **具体 SO 实例**：`item_net_small.asset`、`item_knife.asset`、`item_mine.asset`
- **玩家道具槽**：`PartyPlayer.items: ItemInstance[2]`（`ItemInstance` = 数据 + 当前耐久）

### B2. 开局固定发放（0.1 天）
- `PartyGameManager` 进入 `GamePlaying` 时：所有 Player 塞入 `[net_small, knife]`

### B3. 小渔网 → 影响捕鱼动作（0.5 天）
- Player 触发捕鱼时读当前道具：
  - 有渔网 → 用渔网参数（1 条 / 5s），完成后耐久 -1
  - 无渔网 → 徒手兜底（1 条 / 8s）
- 大渔网留 P2（同结构改数据即可）

### B4. 小刀（1 天）
- Player 按 `UseItem` → 检索附近 1 个身位内正在读秒的其他 Player
- 命中：中断对方 `FishingAction`，小刀耐久 -1，对方渔网耐久 -1（如果有）
- 未命中：小刀不消耗（避免误点浪费）

### B5. 水雷（1 天）
- **新脚本**：`Mine.cs`（场景实体，SphereCollider Trigger，半透明材质）
- Player 按 `UseItem` → 在脚下位置 Instantiate 水雷预制体（岛屿区域禁用）
- 其他 Player 进入 Trigger → 眩晕 5s（Player 状态标志位，禁移动/操作）+ 头顶挂 `FX_Stun_Stars`（临时用旋转 Cube）
- 被炸者可 Interact 捡起水雷（判定：状态 `Stunned` 内可拾）

**阶段 B 里程碑**：5 种道具行为齐全（大渔网可省，用小渔网替代），单机可全流程试玩。

> **只在阶段 A/B 单机稳定后动**——不然改起来极痛。

### C1. Player 网络化（1 天）

- 复用 `Assets/Scripts/OwnerNetworkAnimator.cs`
- 参考现有 `Scripts/Player/Player.cs` 里的 `NetworkObject.OwnerClientId` 用法

### C2. FishingSpot & Fish 主机权威（1 天）
- `FishingSpotSpawner` 只在 `IsServer` 生成，通过 `NetworkObject.Spawn()` 广播
- 捕鱼判定全在主机：客户端 `TryFishServerRpc()` → 主机验证距离/道具/数量 → `SpawnFishOnRaftClientRpc()`
- `FishingSpot.remainFish` 用 `NetworkVariable<int>`

### C3. Island 同步（0.5 天）
- `commonFishCount / goldenFishCount` 用 `NetworkVariable<int>`，UI 直接订阅
- 卸鱼/偷鱼：`ServerRpc` 校验（是否岛主 vs 偷鱼）

### C4. 道具 & 水雷同步（1 天）
- 道具耐久走 `NetworkVariable`
- 水雷生成走 `NetworkObject.Spawn()`
- 小刀命中判定主机权威，客户端仅播特效

### C5. Lobby 接入（0.5 天）
- `KitchenGameLobby.cs` / `KitchenGameMultiplayer.cs` 现有大厅**基本不动**

### C6. 联机测试（0.5 天）

## 关键风险 & 开发建议

1. **先单机，后联网** — 阶段 A/B 不要过早做 NetworkBehaviour，会拖慢玩法验证；等玩法稳定再一次性网络化。
2. **数值全部 SO 化** — `PartyGameConfig.asset` 是唯一真相源，避免代码里硬编码 180s / 5s / 3 条。
3. **别急着接美术** — 阶段 A/B 全用几何体，功能稳定后阶段 D 再替换，避免频繁重挂 Prefab 引用。
4. **保留胡闹厨房主线** — 不删原 GameScene，不动原 Counter 代码，只在新目录（`Scripts/PartyGame/`）加东西。
5. **每阶段一次可玩验证** — A6、B5、C6 三个里程碑各留半天做端到端试玩。
