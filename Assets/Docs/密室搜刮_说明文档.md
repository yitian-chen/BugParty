# BUG派对 · 2D 俯视密室搜刮（含地形起伏与地板塌陷）

Unity 2022 完整工程。**风格统一为 2D 俯视角**，同时保留跳跃与高度差玩法。

---

## 一、10 秒上手

1. Unity 2022.3 LTS，打开或新建项目（URP / Built-in 均可）
2. 把 `Assets/BugParty2D` 拖进 `Assets`
3. 等编译完成，新建空场景
4. 菜单 **BugParty2D ▸ Build Room Scene**
5. **按 Play**

| 按键 | 功能 |
| --- | --- |
| `W A S D` | 移动（按屏幕方向） |
| **`Space`** | **跳跃（可跳上桌子）** |
| `J`（按住） | 搜索容器 |
| `K` | 肘击 |
| `R` | 重开一轮 |

## 二、四项需求的实现说明

### ★需求 1：扩大场景

| | 旧版 | 新版 |
| --- | --- | --- |
| 房间尺寸 | 16×12 | **34×26**（面积 4.6 倍） |
| 地板 | 1 块整平面 | **17×13 = 221 块**独立可塌陷方格 |
| 容器 | 6 个 | **12 个**（8 地面 + 2 桌面 + 4 高台） |
| 出生点间距 | 约 5 米 | 约 26 米 |

地板做成 2×2 米的方格并留 4% 缝隙。缝隙不只是装饰——**玩家要能看清每块地板的边界，才能预判哪一块正在开裂**。

### ★需求 2：地形起伏（可跳上桌子）

先说一个必须解决的技术张力：**纯 90° 垂直俯视看不出「跳上桌子」**——跳跃只是原地放大，桌上桌下分不清。

解决方案是 **正交投影 + 70° 俯角**：
- **正交投影**（`camera.orthographic = true`）→ 无透视变形、远近同尺寸，这才是「2D 感」的真正来源
- **70° 而非 90°** → 保留高度可读性

参考《哈迪斯》《元气骑士》：都是正交斜俯视，观感是 2D，但角色能跳、有高低差。俯角可在 `RoomConfig.cameraPitch` 里 50°–90° 自由调，**想更「平」调到 85，想更立体调到 55**。

另外加了**落地阴影**：离地越高，阴影越小越淡。这是 2D 俯视下判断高度的核心线索，比角色本身的位移更好读。

**三级高度设计**（已用物理公式验证）：

跳跃初速 7.2、重力 22 → 最大跳高 `v²/2g = 1.178 米`

| 层级 | 高度 | 可达性 |
| --- | --- | --- |
| 矮柜 / 椅子 / 踏板 | 0.55 m | ✓ 轻松跳上（余量 0.63） |
| **中央会议桌** | 0.95 m | ✓ 需正常跳（余量 0.23） |
| 四角高台 | 1.45 m | ✗ 直接跳不上 → **必须两段跳**（先上 0.55 踏板，再跳 0.90） |

高台设计成两段跳是刻意的：**它放着稀有度最高的容器（rarityBonus 1.5），跳得上去才有金色 Debug 芯片**。这就让「跳跃」从一个动作变成了一条收益路线。

还加了**斜坡**（用 4 级台阶模拟，靠 `CharacterController.stepOffset = 0.42` 自动爬升），给不熟练跳跃的玩家留一条路。

手感细节：
- **郊狼时间 0.12 秒**——走出桌沿的瞬间还能跳
- **跳跃缓冲 0.12 秒**——落地前提前按跳也会生效
- **空中操控 0.65**——空中能微调但不能完全改向，跳跃有「承诺感」
- **肘击能把人从桌上打下来**（`elbowCanKnockOffLedge`），附带高度差惩罚

### ★需求 3：故障元素

三层叠加，越接近结束越猛：

| 层 | 内容 | 实现 |
| --- | --- | --- |
| **环境** | 天花板碎片持续掉落（含蓝色像素碎片）、家具悬浮抖动 | `CeilingDebrisSpawner`（48 个对象池，零 GC） |
| **警报** | 6 个红灯呼吸闪烁，剩余时间越少频率越快、基础亮度越高 | `AlarmSystem` |
| **画面** | 整体抖动 + 红色边框脉冲 + 横向撕裂条 | `TopDownCamera2D` + `RoomHUD` |

碎片间隔从 1.4 秒 → 0.35 秒，警报周期从 2.4 秒 → 0.45 秒，画面抖动间隔从 6 秒 → 1.8 秒。**每次地板塌陷都会额外触发一次抖动 + glitch**，让塌陷有重量感。

HUD 顶部轮播提示文案（你要求的「正在穿越中」「请尽快修复BUG」）：
```
⚠ 正在穿越中…
⚠ 请尽快修复 BUG
⚠ 地板结构不稳定
⚠ 数据完整性下降
```
常态 3.2 秒一换，紧张时 1.4 秒一换。

### ★需求 4：地板塌陷与衔接下一关

**四态状态机**，每块地板独立：

```
Solid（完好）
  ↓ 到点触发
Cracking（开裂预警 1.8 秒）← 红光闪烁，频率从 4Hz 加速到 16Hz，仍可通行
  ↓
Collapsed（碰撞体移除，成为洞）
  ↓ 终局
Falling（波浪式下坠）
```

**预警阶段必须存在。** 直接塌陷会让玩家觉得被阴；有 1.8 秒预警才能形成「快跑离开」的正向操作。

**搜索阶段：少量随机塌陷**（默认 5 块，你要求的「数量很少」）
- 时间均匀分布在搜索时长的 25%–85% 之间，带少量随机
- **位置避开容器和出生点** 2.2 米半径内，避免玩法被破坏
- 四角出生区的地板标记为 `isProtected`，永不随机塌陷

**掉进洞里的处理**——我选了「受罚」而不是「隐形墙挡住」：

隐形墙会让玩家撞得莫名其妙。改成：
```
掉下去 → 继续下坠 0.9 秒（视觉体翻滚）→ 弹回最近的安全地板
        → 硬直 1.2 秒 → 掉落 1 件道具
```
这样**绕路是玩家自己算出来的决策，而不是被墙教育**。而且复用了终局的掉落动画资产。

**终局全塌陷**：
```
搜索倒计时结束
  ↓
以房间中心为震中，波浪式扩散塌陷（3.2 秒）
  ↓ 等地板塌到 45% 时
所有玩家开始自由下坠 + 翻滚动画
  ↓
Transition 阶段（1.6 秒黑屏过渡）
  ↓
把各人道具写入 CarryOverData，加载 nextSceneName
```

**衔接下一关**：选中 `RoomManager`，把 `nextSceneName` 填成目标场景名即可。留空则停在本场景（单独测试模式），`loopForTesting` 勾选时会自动重开。

道具通过静态类 `CarryOverData` 跨场景传递：
```csharp
// 下一关读取
var redItems = CarryOverData.Get(PlayerColor.Red);   // List<string> of itemId
```

## 四、AI 的两项新能力

`AIBrain` 针对新地形做了增强：

**1. 绕开塌陷的洞**
每帧探测前方 1.6 米，如果是洞就依次尝试 ±45°、±80°、±120° 六个方向，挑第一个安全的走，并锁定 0.5 秒避免抖动。四面都是洞时原地等终局。

**2. 会跳台**
- 容器比自己高 0.5 米以上 → 先跳上去再搜
- 对手在桌上 → 跳上去打
- 跳跃有 0.8 秒冷却，避免像兔子一样乱蹦

可用 `RoomConfig.aiCanJump` 关掉，`aiPitAvoidDistance` 调整探测距离。

## 五、常用调整

全部在 `Assets/BugParty2D/Config/RoomConfig2D.asset`：

| 想要的效果 | 改哪个 |
| --- | --- |
| **画面更「2D」** | `cameraPitch` 调到 85（更平）；调到 55 更立体 |
| 视野更广 | `orthographicSize` 调大 |
| **跳不上桌子** | `jumpVelocity` 调大，或把桌子高度调低 |
| 跳跃太飘 | `gravity` 调大 |
| **塌陷太多/太少** | `randomCollapseCount`（默认 5） |
| 预警时间不够 | `crackWarningTime` 调大（默认 1.8 秒） |
| 掉洞惩罚太重 | `pitfallStagger` 调小、`pitfallItemLoss` 设 0 |
| **警报太吵** | `alarmPeriodUrgent` 调大、`alarmIntensity` 调小 |
| 碎片太多 | `debrisIntervalUrgent` 调大、`debrisPerBurst` 调小 |
| **画面抖动晕** | `screenShakeAmount` 调成 0 |
| 全塌陷太快 | `collapseDuration` 调大 |
| 换主题 | `RoomManager` 的 `Theme`（Fishing / Cooking / Police） |
| **接下一关** | `RoomManager` 的 `nextSceneName` 填场景名 |

## 六、开发中修掉的三个 bug

1. **地面检测漏检**：原来用单线射线从角色中心往下打，站在桌子边缘时会漏检，导致「站着却在掉」的抖动 → 改用 `SphereCast`，半径取 CharacterController 的 0.9 倍
2. **阴影跟着角色转**：阴影原本是玩家子物体，角色转身时方形阴影会明显打转 → 改成独立物体，每帧手动同步 XZ 并强制朝上
3. **终局下坠被碰撞体挡住**：直接改 `transform.position` 会和 CharacterController 冲突 → 下坠前先 `Controller.enabled = false`

## 七、验收清单

按 Play 之后应该能观察到：

**场景与地形**
- [ ] 房间明显比之前大，四个人开局互相离得很远
- [ ] 地板是可见的方格网络（棋盘色 + 缝隙）
- [ ] 走近中央会议桌，按 `Space` **能跳上去**
- [ ] 跳起时**阴影变小变淡**，落地恢复
- [ ] 站在桌上时 HUD 状态显示「站在高处」
- [ ] 四角高台**直接跳不上去**，需先跳旁边的踏板
- [ ] 高台容器搜出的东西更容易是金色芯片（稀有）
- [ ] 走上斜坡不用跳也能爬上矮柜

**故障氛围**
- [ ] 天花板持续掉落灰色碎片和蓝色像素块
- [ ] 剩余 12 秒内，红灯闪烁明显加快、碎片变密
- [ ] 画面边缘出现红色脉冲边框，越急越宽越亮
- [ ] 画面每隔几秒抖动一次，紧张时更频繁
- [ ] HUD 顶部轮播「⚠ 正在穿越中…」等提示

**地板塌陷**
- [ ] 搜索途中会有约 5 块地板**先闪红光抖动**，1.8 秒后塌下去
- [ ] 塌陷瞬间画面抖动 + glitch
- [ ] 塌陷处变成洞，**走过去会掉下去**
- [ ] 掉下去后翻滚下坠 → 被弹回最近的安全地板 → 硬直 → 掉一件道具
- [ ] AI **会主动绕开洞**，不会直愣愣往里走
- [ ] 容器和出生点附近**不会塌陷**

**终局衔接**
- [ ] 倒计时结束，全场地板**从中心向外波浪式塌陷**
- [ ] 地板塌到一半时，四个人开始翻滚下坠
- [ ] 出现「正在穿越到下一个 BUG…」黑屏过渡
- [ ] Console 打印各人携带的道具清单（供下一关读取）
- [ ] `loopForTesting` 勾选时会自动重开

**如果第 3、4、5 条（跳上桌子 + 阴影表现高度）和塌陷部分全部成立，这次的四项需求就都验证通过了。**

## 九、下一步建议

1. **给 AI 加 NavMesh**：目前 AI 绕洞是靠射线探测的启发式方法，在复杂地形（斜坡 + 多层平台）下可能贴墙磨。烘 NavMesh 并用 `NavMeshAgent` 会稳很多，注意需要为不同高度层设置 Off-Mesh Link。
2. **塌陷预警加音效**：`RoomEvents.OnTileCracking` 已经暴露，接一个"咔啦"声 + 低频轰鸣，紧张感会翻倍。
3. **PV 分镜需要更新**：新增的「跳上桌子」「地板塌陷绕路」「全场塌陷掉落」都是很好的镜头素材，尤其**终局全塌陷 + 四人翻滚下坠**这一段，可以直接作为三个关卡之间的统一转场，比原分镜里的「蓝色传送门」更有冲击力。如果要改，我可以重写提示词文档的第 7/9/11 章。
